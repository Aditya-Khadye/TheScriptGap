Script Gap

Overview

The Script Gap is a research framework that identifies writing systems widely used in the real world but under-supported in digital typography. By combining web exposure data, font availability, engineering complexity, and visual diversity into a single Script Servedness Score, it surfaces the highest-impact gaps and provides a data-driven roadmap for prioritizing script support.

Methodology

The Script Servedness Score (SSS) is a weighted composite of four independent signals — each computed from its own data source, min-max normalized to [0, 1], and combined into a single rank that reflects the gap between a script's demand and its supply.

Component details:

  • Exposure — aggregated from HTTP Archive web-crawl request data, ranked by CRUX. Counts font requests per script across the top 10M websites, then log-scaled.
  • Support — distinct font families per script from Google Fonts (Chinese variants merged into Han), supplemented by cleaned HTTP Archive font-name metadata. Log-scaled.
  • Complexity — a fontTools-based composite combining (1) Expansion — required glyph count; (2) Vertical footprint — layout/sizing requirements; (3) Friction — OpenType feature load across contextual joining, Indic conjuncts, ligatures, mark positioning, and RTL. Weighted 50/30/20.
  • Diversity — render 10 standardized reference glyphs per script in each font, embed via a frozen pretrained ViT-B/16, average per font for a "font fingerprint", then take the mean pairwise cosine distance across fingerprints within a script.

A high SSS means the script is well served — readership demand is matched by ample, visually varied fonts that are technically feasible to produce. A low SSS means the opposite: demand outpaces supply, the engineering bar is high, and what fonts do exist tend to look alike.

Data Sources

The Script Gap relies on several data sources to provide a comprehensive analysis of script support in digital typography:

  • HTTP Archive: Provides web crawl request data to measure real-world usage of different scripts.
  • CRUX:Provides website rankings that help to estimate font viewership. The HTTP Archive scans the top 10 million websites using these rankings.
  • Font Repositories: Data from platforms like Google Fonts to evaluate font availability and the similarity between fonts for each script.

Exposure

Exposure is calculated by analyzing the HTTP Archive's web crawl request data to measure the real-world usage of different scripts on the web. The HTTP Archive collects a variety of data on each font request, including a list of unicodepoints that can be mapped to their corresponding scripts. By aggregating this data across the top 10 million websites, we can estimate the demand for fonts supporting each script.

Some important things to note about this data:

  • The data is collected from the top 10 million websites but only on the origin/homepage domain.
  • Since the data comes from the top global websites, it may not fully represent the usage of scripts in all regions.

Support

Support options, community resources, and documentation links.

Include details about the methodology and how the data was gathered

Support is measured by evaluating the number of fonts available for each script. Ideally we would only want to use reliable data sources for this, such as font foundries like Google Fonts, Adobe Fonts, and independent foundries that have a strong web presence. However, since there is no comprehensive database of fonts and their supported scripts currently and we only had Google Fonts data we had to make do.

For the main parts of the research we only use the reliable google data, but for other parts (for example the state of the web) we had to use a combination of google fonts data and estimations based on the HTTP Archive data. The HTTP Archive's font name metadata is very messy and unreliable as the font names are not consistently labeled the same way, but after a decent bit of cleaning we can estimate the number of fonts for each script by looking at the number of unique font names that are associated with requests for each script. This is not a perfect method but it gives us a rough estimate of the number of fonts that exist for each script that are actually being used on the web.

Similarity

The similarity score is calculated by analyzing the visual similarity between fonts within each script. Each glyph is rendered as a png and then a vision model is used to extract an embedding that captures the visual style of the glyph. This is used in the creation of a finger print for each font by computing the average visual style of it's glyphs across a set of common unicode points for the script. Finally comparing the font fingerprints of fonts within the same script using cosine similarity gives us a measure of how visually similar the fonts within a script are to each other. A higher similarity score indicates that the fonts are more visually similar to each other, while a lower score suggests greater visual diversity.

Arabian Script Font Similarity Network

A font network diagram can be used to visualize the relationships between different fonts within a script. The network makes it easy to tell what fonts are visually distinctive and can be utilized as a tool for finding unique typographic styles to grow upon.

In this network diagram, each node represents a font supporting Arabic, and the edges between nodes represent the visual similarity between those fonts based on their fingerprints. The thickness of the edges indicates the degree of similarity, with thicker edges representing higher similarity. By analyzing this network, we can identify clusters of visually similar fonts as well as outliers that may offer unique typographic styles.

The nodes are colored based on their modularity class, which is determined by the Louvain community detection algorithm. In this example, we can see 4 distinct clusters of fonts. The red and green clusters are the largest and demonstrate the main typographic styles for Arabic fonts, while the blue and purple clusters are smaller and contain more unique fonts that may be visually distinct from the main styles.

  • Red cluster: traditional handwritten style with more calligraphic features and sharpness.
  • Green cluster: modern style with smoother curves.
  • Blue cluster: outliers in style containing unique characteristics.

This network visualization also supports images of fonts to be displayed on the nodes. This is a great way to quickly visualize the visual style of each font and compare it to other fonts in the network. This allows us to observe more visually how fonts cluster together and verify that the similarity metric is accurate.

In order to see the font images on the nodes: click 'Appearance' -> 'Nodes' then in the 'Images' sections set the image label to image_url.

Future Work

Future research directions include:

  • Expanding the font database to include more foundries and independent type designers to get a more comprehensive view of font availability for each script and script similarity.
  • Conducting user studies to validate the Script Servedness Score against real-world user experiences as well as the accuracy of the similarity metrics.
  • Further organization of the pipeline and deployment of automated workflows.
  • Growing the scope of the research to include more scripts and languages.
