Overview
What is
The Script
Gap?

Closing the gap between real-world demand and digital font supply.

The Script Gap is a research framework that identifies writing systems widely used in the real world but under-supported in digital typography.

By combining web exposure data, font availability, engineering complexity, and visual similarity into a single Script Servedness Score, it surfaces the highest-impact gaps and provides a data-driven roadmap for prioritizing script support.

Scripts used by billions of readers online remain severely underdeveloped not because the need isn't there, but because infrastructure and market investment has been disportionately focused on Latin. This framework aims to shine a light on the underserved scripts that need more typographic development.

Measuring real-world script usage at web scale.

Exposure is calculated by analyzing the HTTP Archive's web crawl request data. Each font request includes Unicode codepoints that can be mapped to their corresponding scripts aggregated across the top 10 million websites to estimate demand.

Since the data comes from the top global websites, it may not fully represent usage of scripts in all regions.

The data is collected from each site's origin/homepage domain only. The following treemap breaks down script exposure proportionally by number of font requests.

Font availability

Support is measured by counting distinct font families available per script. Ideally this would draw from all major foundries, but with no comprehensive cross-foundry database available, the primary reliable source is Google Fonts data.

The HTTP Archive's font-name metadata while messy was cleaned and merged with Google Fonts data to produce rough estimates of fonts actually in use on the web. It's imperfect, but gives a ground-truth view of real deployment.

Devanagari has a much larger relative font demand than supply. This discrepancy highlights a potential market gap for providers to address.

How hard is a script to support in the first place?

Engineering effort quantified

Complexity is a fontTools based composite pulled directly from each font's OpenType tables. A score near 0 means the script behaves like Latin (cheap to engineer); a score near 1 means heavy technical debt.

50%

Expansion (E)

Glyphs per Unicode codepoint. Latin ≈ 1:1; Arabic needs 4–5×; Devanagari adds conjuncts on top.

30%

Vertical Footprint (V)

Vertical sizing requirements. Scripts with stacked diacritics push this up; flat single-row scripts pull it down.

20%

Friction (F)

OpenType feature load contextual joining, Indic shaping, ligatures, mark positioning, and RTL layout.

Font fingerprints reveal hidden homogeneity.

The similarity score analyzes visual likeness between fonts within each script. Each glyph is rendered as a PNG, then a vision model extracts an embedding capturing its visual style.

Averaging these embeddings across a set of common Unicode points produces a font fingerprint. Comparing fingerprints using cosine similarity gives a measure of how visually alike fonts within a script are.

A high similarity score means the script has many fonts that all look the same quantity without genuine choice.

A lower similarity score indicates more visual variety which is what users actually need.

Final Findings

What the Script Servedness Score reveals.

Least Served: Devanagari

High development complexity combined with high visual similarity among existing fonts means that even though supply appears adequate, users have very few genuinely distinct typographic options.

Best Served: Katakana

Wide font availability paired with genuine visual diversity earns Katakana the highest Script Servedness Score a model for what well-supported scripts look like.

Demand ≈ Supply Mostly

Web exposure and font support are positively correlated across most scripts. The valuable insight lies in the scripts that break this pattern and expose real market gaps.
